# PharmaGO

Поиск лекарств по аптекам Бишкека: цены, наличие, режим работы и ближайшая
аптека на карте. Приложение на **Nuxt 4** с серверным API, Google Maps
и фирменными анимациями.

## Требования

- **Node.js ≥ 22.19** (Nuxt 4.5 не поддерживает Node 20). В репозитории есть
  `.nvmrc` — `nvm use` подхватит нужную версию.
- npm 10+.

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

Сборка и предпросмотр production-версии:

```bash
npm run build
npm run preview
```

Проверка типов: `npm run typecheck`.

> `.npmrc` включает `legacy-peer-deps` — это обход бага арбориста npm 10
> при разрешении peer-зависимостей Nuxt (`Cannot read properties of null
> (reading 'edgesOut')`). На состав дерева зависимостей флаг не влияет.

## Google Maps

Скопируйте `.env.example` в `.env` и подставьте ключ:

```bash
NUXT_PUBLIC_GOOGLE_MAPS_API_KEY=ваш-ключ
NUXT_PUBLIC_GOOGLE_MAPS_MAP_ID=          # необязательно
```

В [Google Cloud Console](https://console.cloud.google.com/google/maps-apis)
включите **Maps JavaScript API** и убедитесь, что ключ не запрещает её
в разделе **API restrictions** — иначе Google вернёт `ApiTargetBlockedMapError`
и карта не отрисуется.

`.env` читают `nuxt dev` и `nuxt preview`. Собранный сервер, запущенный
напрямую (`node .output/server/index.mjs`), файл не читает — там переменные
задаются окружением:

```bash
NUXT_PUBLIC_GOOGLE_MAPS_API_KEY=... node .output/server/index.mjs
```

Ключ Maps JavaScript API виден в браузере по своей природе, поэтому
ограничьте его в консоли по HTTP-referrer (`localhost:3000/*` и ваш домен).

Маркеры — `AdvancedMarkerElement`, для них нужен Map ID. Без своего значения
используется `DEMO_MAP_ID` (годится для разработки). Стиль подложки задаётся
в облачной консоли на этом Map ID: при использовании Map ID параметр `styles`
в коде игнорируется — это ограничение Google, а не приложения.

Карта используется в трёх местах: на главной (обзор сети аптек),
на `/map` (полный список с фильтрами) и на карточке препарата — там
на метках вместо названия сети показана цена в этой аптеке.

**Без ключа сайт полностью рабочий.** Компонент `PharmacyMap` переключается
на `MapFallback` — схематичную карту, где аптеки разложены по настоящим
координатам в равнопромежуточной проекции. Взаимное расположение точек
сохраняется, теряется только подложка. Если API не загрузился, поверх схемы
показывается фирменная анимация «нет сети».

Отказ ключа приходит асинхронно, уже после загрузки скрипта, — его ловит
`window.gm_authFailure`. Состояние переходит в `denied`, мёртвый контейнер
Google снимается, и на его месте появляется схема с подсказкой, что
поправить в консоли.

В центре Бишкека аптеки стоят вплотную, поэтому подписи меток разводятся
от перекрытий. На настоящей карте это делает сам Google
(`collisionBehavior`), на схеме — свой расчёт: прямоугольники подписей
меряются в DOM, перекрывающие гасятся и возвращаются по наведению.
Выбранная аптека подписана всегда.

```

  plugins/auth.ts            подтягивает пользователя до маршрутизации
  pages/                     маршруты
  utils/logo-geometry.ts     геометрия знака (общая для логотипа и анимаций)
server/
  api/                       поиск, аптеки, препараты, брони, заказы, вход
  utils/auth.ts              сессии, коды подтверждения, восстановление

```

## Страницы

| Маршрут | Что делает |
| --- | --- |
| `/` | Главная: поиск, живая витрина выдачи, аналитика, карта, FAQ |
| `/search` | Результаты поиска, все фильтры живут в адресной строке |
| `/medicines` | Каталог препаратов: поиск, категории, рецептурность, цены |
| `/login` | Вход по номеру: код в WhatsApp, восстановление по коду брони |
| `/account` | Кабинет: обзор, заказы, брони, избранные аптеки, профиль |
| `/medicine/[slug]` | Карточка: цены по аптекам, карта с ценами, аналоги, инструкция |
| `/map` | Все аптеки на карте со списком, фильтрами и маршрутом |
| `/reservations` | Мои брони: статус, обратный отсчёт, поиск по коду |
| `/partners` | Тарифы и заявка на подключение аптеки |
| `/about`, `/contacts`, `/terms` | О компании, контакты, документы |

Каждая страница обёрнута в один корневой элемент (`.page-body`) — иначе
`pageTransition` не может её анимировать и при клиентском переходе контент
не отрисовывается.

## Серверное API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/search` | выдача по препарату с фильтрами и статистикой цен |
| GET | `/api/medicines` | каталог: категории, вещества, диапазон цен |
| GET | `/api/medicines/[slug]` | карточка препарата, предложения, аналоги |
| GET | `/api/pharmacies` | аптеки с расстоянием и статусом работы |
| GET | `/api/suggest` | подсказки для поисковой строки |
| GET | `/api/stats` | витринные цифры для главной |
| GET | `/api/reservations/[code]` | статус брони по коду |
| POST | `/api/reservations` | оформить бронь на 3 часа |
| POST | `/api/orders` | оформить доставку |
| GET | `/api/orders`, `/api/orders/[code]` | свои заказы и статус по коду |
| POST | `/api/orders/[code]/cancel` | отмена, пока курьер не выехал |
| GET/POST | `/api/favorites` | избранные аптеки |
| POST | `/api/auth/request-code` | код подтверждения в WhatsApp |
| POST | `/api/auth/verify` | вход по коду, сессия в httpOnly-куке |
| POST | `/api/auth/recover` | «не помню номер» — поиск по коду брони |
| GET | `/api/auth/me` | текущий пользователь |
| PATCH | `/api/auth/profile` | имя и адрес доставки |
| POST | `/api/partners`, `/api/contact` | заявка аптеки и обратная связь |

Телефон принимается в любом написании и нормализуется к `+996XXXXXXXXX`.

Открыто/закрыто и расстояния считаются **на сервере**: разметка после
гидратации совпадает с отрендеренной.

Брони лежат в хранилище Nitro с файловым драйвером (`.data/reservations`),
поэтому переживают перезапуск. Аккаунтов в сервисе нет: список своих броней
браузер держит в `localStorage`, а подробности запрашивает по коду.

## Аккаунт и вход

Пароля нет: логин — номер телефона, подтверждение — шестизначный код,
который уходит в **WhatsApp**. Вход и регистрация — один шаг: аккаунт
заводится при первом подтверждении номера.

Что предусмотрено:

- код живёт 5 минут, повторная отправка не чаще раза в минуту;
- 5 попыток ввода, дальше код сгорает; сверка постоянная по времени;
- сессия — случайный токен в httpOnly-куке на 30 дней, `sameSite=lax`;
- **«не помню номер»** — по коду брони или заказа сервер находит номер,
  показывает его в маске (`+99655• ••• •33`) и выдаёт одноразовый билет.
  Полный номер клиенту не отдаётся, поэтому перебором кодов его не выяснить;
- заказы и брони, оформленные до входа, привязываются к аккаунту, когда
  человек откроет их по коду.

### Подключение WhatsApp

```bash
NUXT_WHATSAPP_TOKEN=...
NUXT_WHATSAPP_PHONE_NUMBER_ID=...
NUXT_WHATSAPP_TEMPLATE=pharmago_otp
```

Реквизиты берутся в [WhatsApp Cloud API](https://developers.facebook.com/docs/whatsapp/cloud-api),
шаблон должен быть категории **Authentication** с параметром `{{1}}` под код.

> **Без этих переменных вход работает в демо-режиме:** сообщение никуда
> не уходит, код пишется в лог сервера и показывается прямо на экране входа.
> Так можно пройти весь сценарий без бизнес-аккаунта. В продакшене
> обязательно задайте реквизиты — иначе код виден любому.

## Заказы

Аптеки со значком «Доставка» принимают заказ на дом: количество, адрес,
комментарий курьеру, оплата при получении. Доставка — 150 сом, ожидание
1–2 часа, отмена возможна, пока курьер не выехал.

Настоящей интеграции с аптеками нет, поэтому статус разыгрывается по времени
от момента оформления: принят → собирается → в пути → доставлен. Логика
собрана в `orderStatus()` и заменяется на данные аптеки одной функцией.

## Данные

Аптеки (24 точки) размещены по настоящим улицам и микрорайонам Бишкека —
координаты реальные, названия сетей, телефоны и расписание демонстрационные.

Цены и остатки генерируются детерминированно: `seededUnit()` хеширует пару
«препарат + аптека», поэтому сервер и клиент получают одинаковые числа.
`Math.random()` здесь сломал бы гидратацию. У каждой сети своя наценка —
разброс цен в выдаче выглядит как настоящий, а не как случайный шум.

Чтобы подключить реальные остатки, замените `buildOffers()` в
`shared/utils/catalog.ts` на запрос к источнику данных — сигнатуры
API-обработчиков менять не придётся.

## Анимации

Фирменные анимации перенесены в Vue-компоненты: SSR-безопасные,
реактивные, без глобального `window.PG`. Геометрия у знака и анимаций общая —
`app/utils/logo-geometry.ts`.

| Компонент | Где используется |
| --- | --- |
| `PgLoader` | загрузка карты, подсказки поиска, уведомления |
| `PgMark` | результат брони и отправки форм (`check` / `fail`) |
| `PgBurst` | осколки вокруг галочки успеха |
| `PgDrain` | сколько осталось до конца брони |
| `PgEmpty` | пустая выдача, пустой список аптек, 404 |
| `PgOffline` | Google Maps не загрузился, ошибка 5xx |
| `PgDots` | кнопки в состоянии «отправляем» |
| `PgSkeletonCard` | загрузка выдачи и списка аптек |
| `PgToaster` | стек уведомлений, монтируется в layout |

Уведомления — через `useToast()`:

```ts
const toast = useToast()
toast.success('Бронь оформлена', 'Код PG-123456')
toast.error('Не отправилось', 'Проверьте телефон')
const dismiss = toast.show({ title: 'Определяем…', duration: 0 })
```

CSS-утилиты: `pg-fade-up`, `pg-fade`, `pg-pop`, `pg-stagger` (каскад с шагом
80 мс), `pg-shake`, `pg-dots`, `pg-progress`, `pg-toggle[aria-checked]`,
`pg-shimmer`, `pg-bounce-down`. Всё уважает `prefers-reduced-motion`.

## Оговорка

Цены, остатки, телефоны и реквизиты — демонстрационные. Информация
о лекарственных средствах носит справочный характер и не заменяет
консультацию врача.
